\chapter{Requirements analysis}
\label{chap:besoin}

\section{Objectives of the assignment}
The theme of the internship translates into four concrete objectives: (1) secure access to the server and its transport layer before any exposure; (2) industrialise the deployment process so that a code change reaches production reliably and quickly; (3) host several independent web applications on the same infrastructure without them interfering with one another; (4) supervise the whole platform so that its state (resource usage, running applications, security events) is visible at a glance rather than discovered after the fact.

\section{Constraints}
Three constraints shaped almost every technical decision made during the internship:
\begin{itemize}
  \item \textbf{Budget}: effectively zero for software — every tool used had to be free or open-source, which is why the stack leans heavily on self-hosted and free-tier services (Let's Encrypt, Cloudflare's free plan, DuckDNS) rather than paid alternatives.
  \item \textbf{Network}: the server's Internet connection turned out to be a shared Starlink link behind Carrier-Grade NAT (CGNAT) on IPv4, with no public IPv4 address and no port forwarding available — a constraint discovered only once the classic reverse-proxy approach (Traefik with a directly exposed port) had already been implemented, forcing a redesign (see chapter~\ref{chap:securisation}).
  \item \textbf{Time}: 16 weeks, which required prioritising security hardening and a first working application early, and treating multi-application hosting and advanced supervision as later, incremental additions rather than a big-bang delivery.
\end{itemize}
